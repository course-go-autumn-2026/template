Инструмент: `gremlins` v0.6.0, Go 1.26.5. Проверены все пакеты с кодом в
`internal/domain/...` и `internal/usecase/...`. Отчёт содержит исторический
результат до дополнения тестов и новый прогон текущего кода после изменений.

### Разбор пробелов

Пять выживших в домене изменяли строгое сравнение на нестрогое: допустимые
значения `price = 0`, `latitude = -90` или `90`, `longitude = -180` или `180`
становились недопустимыми. В [тесты домена](../internal/domain/trip/trip_test.go)
добавлены эти пять граничных значений. Невалидные значения за пределами границ
тоже проверяются.

Непокрытая мутация в `create` относилась к проверке ошибки
`CompleteIdempotencyKey`. В [тесте создания](../internal/usecase/trip/create/usecase_test.go)
есть сценарии успешного создания с ключом и ошибки завершения ключа; последний
проверяет, что ошибка возвращается вызывающему коду.

Числа до и после нельзя напрямую сравнивать как результат одного эксперимента:

две из них не компилируются. Даже скорректированный показатель ниже не
доказывает отсутствия других ошибок.

### Проверка компиляции и выполнения тестов

Каждая из 34 мутаций из отчётов воспроизведена отдельно: сначала пакет вместе
с тестами компилировался через `go test -c -vet=off`, затем скомпилированный
тестовый бинарный файл запускался с `-test.failfast`. Подробности, включая
упавшие тесты или ошибку компиляции, сохранены в [audit.json](mutation-results/audit.json).
Исходные файлы проекта не изменялись: применялся Go overlay.

| Пакет | Тесты обнаружили | Ошибка компиляции | Выжило |
|---|---:|---:|---:|
| `domain/trip` | 21 | 2 | 0 |
| `usecase/trip/create` | 8 | 0 | 0 |
| `usecase/trip/finish` | 3 | 0 | 0 |
| **Итого** | **32** | **2** | **0** |

Две ошибки компиляции — `ARITHMETIC_BASE` на строках `trip.go:63` и `:67`:
оператор `+` в выражениях вида `field + ".latitude"` заменён на `-`, который
не применяется к строкам. Это нежизнеспособные мутации, а не успех тестов.
Из 32 мутаций, дошедших до запуска, ни одна не выжила. При этом среди них
есть одинаковые преобразования `-` в `+`, созданные разными операторами;
они посчитаны как отдельные записи gremlins, а не независимые ошибки.

Для повторной проверки сохранённых отчётов выполните
`python3 scripts/audit_mutations.py`. Скрипт использует текущие исходники и
координаты из JSON; после изменения кода сначала заново создайте отчёты gremlins.
При ошибке компиляции мутанта он записывает её в результат, а не считает
падением теста; ненулевой код завершения означает выжившего мутанта или сбой
проверки.

`INVERT_BITWISE` намеренно исключён из итогового прогона. В gremlins v0.6.0
он также применяется к унарному `&` при создании указателей. Это может привести
к некомпилируемому коду, а инструмент классифицирует завершение `go test` с
кодом 1 как `KILLED`, не отличая ошибку сборки от падения теста. Поэтому такой
результат нельзя использовать как свидетельство качества теста.

## Как повторить

Установите инструмент:

```sh
go install github.com/go-gremlins/gremlins/cmd/gremlins@v0.6.0
```

Выполните из корня репозитория (добавьте `$GOPATH/bin` в `PATH`):

```sh
for pkg in domain/trip usecase/trip/create usecase/trip/get usecase/trip/finish; do
  gremlins unleash "./internal/$pkg" --workers=2 --timeout-coefficient=10 \
    --invert-logical --invert-assignments --invert-bwassign \
    --invert-loopctrl --remove-self-assignments
done
```

Числа могут отличаться после изменения исходного кода или версий инструментов.
