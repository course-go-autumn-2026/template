# Координаты и опрос устаревших поездок

Сервис сохраняет маршрут, выбирает устаревшие активные поездки порциями и запрашивает координаты через ограниченный пул воркеров. Очередь учитывает приоритет по времени последней координаты, вытесняет более свежие задачи и отменяет ожидающие задачи при поступлении координаты.

Проверено: `go test -race -count=2 ./...`, интеграционные тесты с PostgreSQL, `make lint`; под нагрузкой 200 поездок с очередью на 10 задач и задержкой Push Service 5 секунд сервис отвечал на запросы и фиксировал переполнение. [Метрики под нагрузкой](lab3-metrics.png). План запроса с продолжением на 10 000 поездок: [EXPLAIN ANALYZE](lab3-explain.txt), используется `trips_stale_position_idx`.
